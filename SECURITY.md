# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability, please report it responsibly:

- Email: [mithungowda.b7411@gmail.com](mailto:mithungowda.b7411@gmail.com)
- Do NOT open a public issue for security vulnerabilities

We will acknowledge your report within 48 hours and provide a fix as soon as possible.

## Bug Bounty

This project does **not** have a bug bounty program. We appreciate responsible disclosure but cannot offer monetary rewards.

## Scope

- Authentication or session bypass on the admin API (`/api/admin/*`)
- Bypassing validation or rate limiting on the public analytics endpoint (`/api/generations`)
- XSS or injection in the generators or the admin dashboard
- Exposed credentials or secrets in the repository or Docker images
- Weaknesses in the shipped nginx or Docker configuration
- Ways for a pull request or workflow change to run untrusted code on the self-hosted deploy runner

## Out of Scope

- The public analytics endpoint is intentionally unauthenticated (it only inserts validated rows)
- Client-side code is fully visible by design (static site)
- Issues that require physical access to the user's device
- Misconfigured deployments that ignore the documented setup (for example, running without HTTPS)

## Hardening Notes for Operators

- Keep `.env` out of version control and use long random values for `POSTGRES_PASSWORD`, `ADMIN_PASSWORD` and `SESSION_SECRET`. On the OSSC server these live in `/srv/server-data/<env>/pagecraft/pagecraft.env` (root:pagecraft, mode 640) and are generated by `deploy/setup-environment.sh`.
- TLS ends at Cloudflare; nginx listens on loopback only and restores the visitor IP from `CF-Connecting-IP`. Keep `TRUST_PROXY=1` and `COOKIE_SECURE=true` so the admin cookie is only ever sent over HTTPS. Without the tunnel, terminate TLS at nginx (`nginx/conf.d/tls.conf.example`).
- Do not publish the database port. The compose file keeps PostgreSQL on the internal network only.
- The deploy runner has Docker access on the server, which is root-equivalent. Only code merged into `dev` or `master` reaches it: both branches require a pull request with passing CI, and workflow runs from forks need maintainer approval. Review every change under `.github/` and `deploy/` before approving.
- Rotate a secret by editing the env file and running `sudo pagecraft <env> compose up -d app`; the database password additionally needs `ALTER USER` inside PostgreSQL because the volume keeps the old one.
- Roll back a bad release with `sudo pagecraft <env> rollback`; images of the last five releases per environment are kept on the server.
